# Генератор бюджета ФОТ Alfa-Service — инструкция по развёртыванию

## 1. Главный архитектурный вывод (прочитать перед началом)

За время разработки этого инструмента мы перепробовали три подхода к выгрузке
цветного Excel и два из них **не работают надёжно**:

| Подход | Результат |
|---|---|
| SheetJS (`xlsx.js`) в браузере, флаг `cellStyles:true` | ❌ Не работает. Проверено байт-в-байт: библиотека физически не записывает пользовательские цвета/заливки в `styles.xml`, только дефолтные. Это ограничение бесплатной версии, а не баг кода. |
| ExcelJS в браузере через CDN (`cdnjs`, `jsdelivr`) | ❌ Ненадёжно. Корпоративные фаерволы/антивирусы (например, Касперский) блокируют загрузку по эвристике на большие минифицированные JS-файлы. Тот же результат при полном встраивании библиотеки (~900 КБ) прямо в HTML — блокируется по тем же эвристикам. |
| **Python + openpyxl на сервере** | ✅ **Работает всегда**. Никаких сетевых запросов на клиенте, никаких сторонних JS-библиотек для стилизации. |

**Вывод: вся логика построения цветного файла должна выполняться на сервере.**
Клиент (браузер) только загружает исходный `.xlsx` и получает готовый файл в ответ.
Это не архитектурная прихоть — это единственный проверенный рабочий путь.

## 3. Форматы исходных файлов (штатный шаблон Альфа-Сервис)

Приложение должно распознавать **два формата** одного и того же шаблона:

### Формат A — лист «Штат» (помесячная разбивка)
Данные уже разбиты по месяцам блоками. Пример: файл «Лефортово».
Колонки: B=должность, C=кол-во, D=график, E=ставка/смену, F=ЗП на руки, I=ЗП на всех.

### Формат B — лист «Расчет ФОТ» (один период)
Единый блок на весь срок контракта, посчитанный из часов. Пример: файлы OZON,
НЕБО, Завод «Святой Источник», ВИ.ру.
Колонки (могут смещаться, нужно искать заголовок «Кол-во, чел.» динамически):
B=должность, C=кол-во, D=график, H=кол-во месяцев, J=ЗП в месяц, K=ставка за смену.

**Правило:** искать оба листа по названию (regex `/^штат$/i` и `/расчет.{0,5}фот/i`),
использовать тот, что найден. Никогда не полагаться на фиксированные номера строк —
искать строку заголовка динамически по тексту «Кол-во, чел.».

## 4. Бизнес-правила расчёта смен (критически важно)

### 4.1. Графики работы

| График | Формула количества смен в месяц |
|---|---|
| `7/0` | Все календарные дни месяца |
| `5/2` | Рабочие дни (пн–пт) конкретного месяца |
| `6/1` (сама по себе, без пары) | `round(дней_в_месяце × 6/7)` ≈ 26–27 |
| `1/6` (сама по себе) | `round(дней_в_месяце × 1/7)` ≈ 4–5 |
| `3/4` | Пятница + суббота + воскресенье месяца |
| `2/2` | `round(дней_в_месяце / 2)` |
| Любой `N/M` | `round(дней_в_месяце × N / (N+M))` |

### 4.2. Критическое правило объединения 6/1 + 1/6

В штатных файлах одна должность часто представлена **двумя строками**: основной
персонал (график `6/1`) и подменный/резервный (график `1/6`), с одинаковыми
кол-вом человек и сроком контракта. **Эти две строки нужно объединить в одну**,
потому что вместе они покрывают **все дни месяца**:

```python
# Признак пары: одинаковая должность, кол-во людей, срок контракта,
# и графики "6/1"+"1/6" (в любом порядке)
if pos_a == pos_b and qty_a == qty_b and months_a == months_b:
    if {sched_a, sched_b} == {'6/1', '1/6'}:
        merged_schedule = '7х0'          # теперь работает каждый день
        merged_salary   = sal_a + sal_b  # суммируем ЗП обеих строк
        rate            = rate_a         # ставка одна и та же в обеих строках
```

Если пары нет (в файле только одна строка `6/1` без парной `1/6`) — считать
смены **пропорционально** по формуле выше (round(дней×6/7)), не «все дни».

### 4.3. Ставка за смену — ФИКСИРОВАННАЯ, не пересчитывать

В исходном файле столбец K («ставка за смену») содержит **фиксированное число**
(например, 3900 ₽ для ОПУ, 5100 ₽ для тракториста). Это число одинаково для
графика `6/1` и `1/6` одной и той же должности.

**Частая ошибка**: пересчитывать ставку как `ЗП_в_месяц ÷ количество_смен`.
Это неверно — ставка «плавает» между месяцами с разным числом дней, хотя должна
быть постоянной. **Правильно**: взять ставку из столбца K один раз, использовать
её как константу, а меняться от месяца к месяцу должно только **количество смен**
(из-за разного числа дней в календаре) и, соответственно, итоговая сумма.

```python
rate_fixed = row['ставка_за_смену']   # константа, из файла, не пересчитывать
for month in contract_months:
    shifts = calc_shifts(schedule, month.year, month.month)  # варьируется
    salary_all = rate_fixed * shifts * qty                    # варьируется
```

### 4.4. Автоматическое определение окладников

Должности, в названии которых встречается один из корней (без учёта регистра):
`менеджер`, `управля`, `директор`, `руковод` — по умолчанию считаются
**окладниками** (фиксированная месячная зарплата, не зависящая от смен).
Для них: `ЗП_на_всех = оклад × кол-во_человек`, количество смен и ставка не
показываются (прочерк).

Это правило — **умолчание**, которое пользователь может переопределить вручную
для конкретной должности в конкретном месяце (см. раздел про переключатель
Фикс/Смена ниже). Ручной выбор должен иметь приоритет над автоправилом.

### 4.5. Сезонная активность должностей

Некоторые должности (обычно с сроком контракта не 12 месяцев, а 4, 5, 7 или 8)
работают только часть года:

| Признак в названии | Кол-во месяцев в файле | Активные месяцы |
|---|---|---|
| содержит «лет» | 8 | Март – Октябрь |
| содержит «лет» | 7 | Апрель – Октябрь |
| содержит «зим», «трактор», «снег» | 4 | Ноябрь – Февраль |
| содержит «зим», «трактор», «снег» | 5 | Ноябрь – Март |
| нет признака, `months == 12` | — | Круглый год |

### 4.6. Частичные месяцы (дата выхода не 1-го числа)

Если сотрудники выходят не с начала месяца (например, «выход 15 августа»), то
первый и последний месяцы периода — **неполные**. Считать доступные дни как
конкретный диапазон `[d1, d2]` внутри календарного месяца, а не весь месяц:

```python
# Пример: контракт с 15.08.2026 по 14.08.2027 (ровно 12 месяцев = 365 дней)
month_specs = [
    (2026, 8, 15, 31),   # частично: с 15 по 31 августа = 17 дней
    (2026, 9, 1, 30), (2026, 10, 1, 31), ...,  # 11 полных месяцев
    (2027, 8, 1, 14),    # частично: с 1 по 14 августа = 14 дней
]
for (yr, mn, d1, d2) in month_specs:
    available_days = d2 - d1 + 1
    shifts = available_days  # для графика 7х0 — все доступные дни периода
```

Оклад в частичный месяц пропорционален: `оклад × (доступные_дни / дней_в_месяце)`.

## 5. Расходы и материалы (лист «Калькуляция»)

Все шаблоны Альфа-Сервис используют одинаковую структуру строк на листе
«Калькуляция» (номера строк стабильны между разными файлами одного шаблона):

| Категория | Строка | Столбец |
|---|---|---|
| Расходные материалы (химия) | 16 | F (сумма в месяц) |
| Инвентарь | 21 | F |
| Спецодежда | 30 | F |
| Амортизация ОС (оборудование) | 39 (итого), 41–52 (детализация построчно) | F |
| ГСМ | 48 | F |
| Эксплуатация и ремонт | 55 | F |

Детализация оборудования (строки 41–52): столбец B=название, C=кол-во,
D=цена покупки, E=срок амортизации (мес.), F=сумма амортизации в месяц.

**Признак аренды**: если в названии позиции оборудования встречается слово
«аренда» — это не собственное оборудование, а лизинг/аренда. Такие позиции
нужно **помечать отдельно** (не путать с амортизацией собственного) и
исключать из скидок/пересчётов, если пользователь просит применить скидку
только к расходникам.

## 6. Согласованность округления (важный нюанс)

Если в таблице показывается сумма «в месяц» и «за весь период», округлять
**сначала месячную величину**, а «за период» считать уже от округлённого
числа. Иначе при проверке вручную (месяц × количество_месяцев) цифры не
сойдутся с показанным периодом:

```python
# НЕПРАВИЛЬНО — легко получить рассинхронизацию округления:
month_val  = round(raw_value)            # напр. 7292
period_val = round(raw_value * months)   # напр. 131250 (не равно 7292*18!)

# ПРАВИЛЬНО:
month_val  = round(raw_value)            # 7292
period_val = month_val * months          # 7292*18 = 131256 — сходится
```

## 10. Живые формулы Excel (не готовые числа)

По умолчанию `excel_builder.py` пишет в файл **формулы**, а не заранее
посчитанные Python-значения. Входные данные (ставка, кол-во человек, смены,
оклад) — константы; все производные суммы — формулы `=ссылка*ссылка`:

```
ЗП 1 сотр. на руки  = Ставка × Смены                    (=F10*H10)
Итого смен            = Кол-во × Смены                    (=C10*H10)
ЗП на всех             = Ставка × Итого смен               (=F10*I10)
Итого по месяцу        = SUM(ЗП на всех по должностям)     (=SUM(J9:J16))
Итого за период        = SUM(Итого по месяцам)             (=SUM(J...:J...))
```

Для окладников (Фикс): `ЗП на всех = Оклад × Кол-во` (`=G10*C10`).

**После генерации файла формулы обязательно нужно проверить** — Excel и
LibreOffice сами пересчитывают формулы при открытии, но чтобы убедиться,
что нет ошибок (`#REF!`, `#VALUE!`) ещё до отправки файла пользователю,
прогоните его через headless-пересчёт LibreOffice:

```bash
soffice --headless --convert-to xlsx --outdir /tmp /path/to/file.xlsx
# или скриптом, который пересчитывает и возвращает JSON с количеством ошибок
```

После пересчёта откройте файл с `data_only=True` в openpyxl и проверьте,
что в нужных ячейках нет `None` там, где ожидается число, и нет строк вида
`#REF!`/`#VALUE!`/`#DIV/0!`.

## 11. Ручное переопределение Фикс/Смена

Автоправило (раздел 4.4) распознаёт как окладников только должности с
корнями «менеджер/директор/руководитель». Если по факту какая-то другая
должность (например, «Ночной Администратор») тоже на фиксированном окладе —
это нужно указать явно через параметр `oklad_overrides` в `build_months()`:

```python
months = build_months(
    parsed, start_month=7, start_year=2026, n_months=12,
    oklad_overrides={'ночной администратор': True},  # форсируем Фикс
)
```

Сравнение — по вхождению подстроки в название должности (без учёта
регистра). Можно и наоборот — снять Фикс с должности, которая по названию
похожа на менеджера, но по факту посменная: `{'менеджер уборки': False}`.

В веб-форме это поле называется «Переопределить Фикс/Смена» и принимает
строку вида `ночной администратор:1,менеджер уборки:0` (1 = Фикс, 0 = Смена).



Если придёт файл с непривычной структурой:

1. Проверить оба варианта названия листа: `Штат` и `Расчет ФОТ`.
2. Найти строку заголовка динамически (искать текст «Кол-во» + «чел»), не
   полагаться на фиксированный номер строки.
3. Проверить, есть ли пары `6/1`+`1/6` для одной должности — объединить.
4. Проверить, фиксирована ли ставка в столбце K, или её придётся считать из
   `ЗП_в_месяц / стандартное_число_смен_в_файле` (обычно тоже есть готовое
   число смен в столбце с заголовком «Кол-во рабочих смен в месяц»).
5. Проверить название заказчика в Калькуляции (строка с меткой «заказчик»,
   НЕ «объект» — есть баг-ловушка: строка «Вид объекта» тоже содержит слово
   «объект» и может случайно перехватить название вместо реального заказчика).
6. Если поле заказчика пустое — сформировать имя из имени файла, а не
   показывать техническое поле вроде «Недвижимость/Логистическая».

## 12. Секционные маркеры сезонности (ЛЕТО/ЗИМА)

Некоторые файлы (например, ЦСКА Автозаводская) размечают сезонность не
только в названии должности, а явными строками-маркерами «ЛЕТО» / «ЗИМА»
(без количества человек), после которых все последующие строки до
следующего маркера относятся к этому периоду — даже если в названии
должности нет сезонных слов («Старший менеджер Объекта» тоже может
встречаться дважды, в обеих секциях, с одинаковыми qty/rate).

`_parse_raw_staff()` отслеживает такие маркеры и сохраняет их в поле
`section_season`, которое имеет приоритет над определением по названию
в `is_position_active()`.

## 13. Объединение пар 6/1+1/6 — проверка по ставке

**Критически важно**: одна и та же должность может встречаться в файле
несколько раз с РАЗНЫМИ ставками (например, ВИ.ру: «ОПУ/ОПМ, день» —
12 человек по 3700 ₽/смену и ещё 8 человек по 3500 ₽/смену — это две
разные группы, не пары 6/1+1/6 одной группы).

`merge_shift_pairs()` объединяет строки в пару 6/1+1/6 только если
совпадают **и** должность, **и** количество человек, **и** срок контракта,
**и** ставка (`rate_fixed`), **и** сезонная секция. Без проверки ставки
разные по деньгам группы могли бы случайно слиться в одну — это баг,
на который стоит обращать внимание при отладке новых форматов файлов.

## 14. Итог раздела «Расходные материалы» — не путать со строкой «химия»

Строка 16 листа «Калькуляция» — это ИТОГ всего раздела «Расходные
материалы» (химия + мешки для мусора + прочее). Строка 17 — только
подкатегория «химия», которая может быть равна нулю, даже если общий
итог раздела (строка 16) положительный (например, весь бюджет ушёл на
мешки для мусора, а не на химию). **Использовать нужно строку 16**, а не 17
— это реальный баг, который был найден и исправлен при работе над ЦСКА.

### Шаг 2 — Подготовить файл запуска для продакшена

Flask со встроенным сервером (`app.run()`) не подходит для реальной
нагрузки — нужен production-сервер `gunicorn`. Добавить в
`requirements.txt`:

```
flask>=3.0
openpyxl>=3.1
gunicorn>=21.0
```

Создать файл `Procfile` (без расширения) в корне проекта:

```
web: gunicorn app:app
```

### Шаг 3 — Создать сервис на Render.com

1. Зарегистрироваться на render.com (можно через GitHub-аккаунт).
2. **New → Web Service** → выбрать репозиторий `alfa-budget-app`.
3. Настройки:
   - **Runtime**: Python 3
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `gunicorn app:app`
   - **Plan**: Free (для внутреннего инструмента достаточно)
4. Нажать **Create Web Service** — сборка займёт 2–3 минуты.
5. После сборки Render выдаст постоянную ссылку вида
   `https://alfa-budget-app.onrender.com` — это и есть «отдельная страница»,
   которую можно разослать коллегам.

### Особенности бесплатного тарифа Render

- Сервис «засыпает» после 15 минут без запросов — первое открытие после
  паузы займёт ~30 секунд (сервис «просыпается»), дальше работает быстро.
- Если это неприемлемо — платный тариф Render (~$7/мес) убирает засыпание,
  либо альтернатива — **Railway.app** (похожий процесс, свой бесплатный
  лимит) или **PythonAnywhere** (специализируется на Python/Flask,
  бесплатный тариф не засыпает, но домен вида `username.pythonanywhere.com`).

### Альтернатива: свой сервер (VPS)

Если в компании уже есть сервер/VPS:

```bash
# на сервере:
sudo apt install python3-pip nginx
pip install -r requirements.txt gunicorn --break-system-packages
gunicorn --bind 127.0.0.1:8000 app:app --daemon

# nginx конфиг (/etc/nginx/sites-available/alfa-budget):

    listen 80;
    server_name budget.вашкомпания.ru;

```

Дальше — привязать домен и (желательно) настроить HTTPS через `certbot`.

### Что НЕ нужно менять при деплое

Вся бизнес-логика (`budget_engine.py`, `excel_builder.py`) не зависит от
того, где запущен Flask — те же файлы работают и локально, и на Render,
и на VPS без изменений. Деплой касается только `app.py` (добавить
`gunicorn` вместо `app.run()`) и `requirements.txt`.

## 16. Новое: производственный календарь, мультигодовой период, живой переключатель Фикс/Смена

### 16.1. Производственный календарь РФ (`production_calendar.py`)

Раньше количество рабочих дней при графике 5/2 считалось наивно (просто
пн-пт по календарю). Это ошибочно в месяцах с праздниками — например,
январь 2026 года содержит только **15** рабочих дней (не ~21, как дал бы
наивный подсчёт), из-за новогодних каникул.

Новый модуль хранит официальные данные КонсультантПлюс по годам:

```python
from production_calendar import workdays_5x2
n, is_official = workdays_5x2(2027, 1)  # -> (15, True)
```

**Как обновлять на новый год**: как только Постановление Правительства РФ
о переносе выходных на следующий год опубликовано (обычно в сентябре
текущего года), добавьте месяцы в `PRODUCTION_WORKDAYS` в файле —
источник: https://www.consultant.ru/law/ref/calendar/proizvodstvennye/<год>/

Если год не подтверждён в таблице, используется приближённый подсчёт
(пн-пт без праздников) — с явным предупреждением через `is_official=False`.

### 16.2. Мультигодовой период от произвольной даты

`build_months_from_date(parsed, start_date, n_years, oklad_overrides=None)`
в `budget_engine.py` — строит период от РЕАЛЬНОЙ даты начала оказания услуг
(не обязательно 1-е число). Если дата не с 1-го числа — первый и последний
месяцы автоматически становятся частичными, с корректным подсчётом рабочих
дней внутри диапазона (не просто «доступные календарные дни»).

```python
import datetime
months = build_months_from_date(parsed, datetime.date(2026, 9, 24), n_years=1.5)
```

**Важное бизнес-правило**: Фикс-оклад НЕ пропорционируется по частичному
месяцу — платится полностью независимо от даты выхода на объект. Для
посменных (Смена) должностей частичный месяц считает реальные рабочие смены
внутри диапазона (по графику 5/2 — через производственный календарь).

### 16.3. Живой переключатель Фикс/Смена прямо в Excel

`excel_builder.py` теперь САМ создаёт выпадающий список «Фикс»/«Смена»
только в ПЕРВОМ месяце появления каждой должности — с жёлтой заливкой
ячейки. Остальные месяцы этой же должности содержат формулу-ссылку
(`=E26`) на первую ячейку, и формула ЗП (`=IF(E26="Фикс",G×C,F×I)`)
автоматически переключается.

**Как это выглядит для пользователя**: меняете тип один раз в первом
месяце контракта — все остальные месяцы этой должности на весь срок
пересчитываются сами, без повторного открытия программы.

**Ограничение**: если должность была Фикс (столбцы «Ставка»/«Смен»/«Итого
смен» показывают прочерк «—»), а пользователь переключил её на «Смена» —
нужно вручную вписать реальную ставку в колонку F того месяца, иначе
формула вернёт ошибку `#VALUE!`. Осознанный компромежуток ради чистоты
отображения: если приоритет — не ошибаться при переключении, можно вместо
прочерка подставлять число, скрытое белым шрифтом (см. историю правок
файла Техноимпульс в этом чате как пример такого варианта).

### 16.4. Новый флоу веб-формы (двухшаговый)

   найденных должностей с автоопределённым Фикс/Смена
2. Форма показывает чекбоксы-переключатели для каждой должности (можно

3. Кнопка «Сформировать бюджет» → `/api/budget` строит файл с учётом всех
